# 写作准则：为人类读者写作

这套准则沉淀自真实的写作迭代：blog 初稿被用户逐条纠正；后来 README 对照返工，又补上了两课——段落要有主旨，指引要写读者的任务。前三节适用于一切成文，后三节针对 blog。产出前逐条自检。

## 段落：一段一个主旨

- 每段先立主旨句，其余句子都是对主旨的支撑。并列的事实堆不是段落：要么给它一个论断做主旨，要么改写成清单。
- 自检：读完一段，能否用一句话复述它的意思。复述不出来，主旨就没有立起来，段落是散的。
- 一段装不下的意思，拆成两段；同一层次的并列项，用清单，不靠分号硬连。

## 排版：人类读者优先

- 段间空行，长句拆短。
- 需要分层时用 header，不用加粗段落标签。
- 加粗看频率和重心：全文至多两三处，只落在真正的重心（核心规律、结尾金句）。
- 过多的加粗和格式吸引，会分散人类读者的注意力，降低阅读时的启发性思考。
- 引用块、代码块、表格自带视觉区分，不再叠加粗体。
- 核心论断可以独立成段，前后留白，给它呼吸感。

## 指引：写读者的任务，不写系统的步骤

- 从读者的意图写起：读者说"要什么、从哪里来"，克隆、复制、清理这类实现细节留给执行方，不占指引。
- 危险操作不进指引（删除、覆盖、rm -rf 之类）。指引里出现它们，说明写的是实现步骤，不是读者任务。

## 视角：AI 是叙述主体

- 全文以 AI 第一视角记述：是 AI 在帮用户解决问题，不是转述用户的自述。
- 用户的原话放引用块（>），与 AI 的叙述在排版上分层；原话保持原样，不改写。
- 归纳与转述放在引用块之外，转述不伪装成引用。

## 定位：只讲来龙去脉

- blog 记录问题如何长成方法：困境、追问、转折、结论。
- 操作性内容——规则清单、提示词模板、安装步骤——属于 skill，不进 blog。
- 理论作为"故事的结局"嵌入叙事，不写成独立论文。

## 诚实：引用必须真实

- 引用块里的内容必须来自真实对话，不虚构"原话"。
- 无法逐字引用时，用叙述转述，不要伪造引号。
